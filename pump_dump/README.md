# Pump-and-revert-to-trend detector

**Hypothesis being tested.** Some large S&P 500 stocks recently had a
"pump and dump" shape:

1. a phase of rapid price increase (the **pump**),
2. followed by a fall (the **dump**),
3. that settles **slightly above where the pump started**, at roughly the level
   the stock would have reached anyway if it had kept growing along its
   pre-pump trend.

The code below finds each stock's most prominent recent pump, measures where the
price settled compared with that pre-pump trend, and scores how well the
hypothesis fits. It also checks whether the fit is better than chance.

## Quick start

```bash
pip install -r requirements.txt

python -m pump_dump.run_analysis                 # top-50 S&P 500, ~3y daily data, Yahoo -> Stooq fallback
python -m pump_dump.run_analysis --vs-market     # same, on price / SPY (removes market-wide moves)
python -m pump_dump.run_analysis --tickers NVDA AMD MU --n-null 500
python -m pump_dump.run_analysis --source csv --csv-dir my_prices/   # offline: <TICKER>.csv files
python -m pump_dump.run_analysis --synthetic     # smoke test on planted patterns (not market data)
python -m pump_dump.validate_synthetic           # detector accuracy on known shapes
```

Outputs go to `results/`:

| File | Contents |
|---|---|
| `REPORT.md` | aggregate verdict + per-stock table, linked to charts |
| `results.csv` | every metric for every stock |
| `summary_reversion.png` | reversion ratio per stock; the hypothesis predicts r ≈ 1 |
| `charts/<TICKER>.png` | price, fitted episode, and the no-pump trend counterfactual |
| `summary.json` | config, aggregate stats, data-load errors |

## Method

### 1. Episode model (per stock, log price `y`)

Within a **local window** `[t0 − 252d, t2 + 63d]`:

```
y(t) = a + b·t                    one straight log-trend line (constant growth rate)
     + h · tent(t; t0, t1, t2)    rises from 0 at t0 to 1 at the peak t1, then back to 0 at t2
     + d · settle(t; t1, t2)      0 until t1, ramps to 1 at t2, stays at 1 afterwards
```

* `h` = how far above trend the peak was (the pump, log units)
* `d` = how far above trend the price settled after the dump
* **reversion ratio `r = 1 − d/h`** is the key quantity:

| r | Meaning | Shape label |
|---|---|---|
| ≈ 1 (within ±0.4) and settle > start | fell back onto the pre-pump trend, above the start price — **the hypothesis** | `pump_revert` |
| ≈ 1, settle < start | back on trend, but the local trend was falling | `pump_revert_below_start` |
| ≈ 1, but price fell < 8% from the peak | went sideways until the rising trend caught up — no real dump | `plateau_trend_catchup` |
| 0.3 – 0.6 | gave back only part of the pump | `partial_revert` |
| < 0.3 | kept the gains (pump & hold) | `pump_hold` |
| < 0 | kept rising after the "peak" | `continued_rise` |
| > 1.4 | crashed below the trend | `crash_below_trend` |

Because one trend line (`a + b·t`) covers both the pre-pump and post-dump data,
`d ≈ 0` is exactly the claim "it returned to where linear growth would have put it."

**Fitting.** For fixed breakpoints `(t0, t1, t2)` the model is linear in
`(a, b, h, d)`, so each candidate is solved in closed form using prefix sums
(checked against brute-force `lstsq`). All breakpoints are searched on a 5-day grid,
then refined at 1-day resolution. Constraints:

* the pump lasts 5–126 trading days ("rapid" = up to ~6 months),
* the dump lasts 5–252 days,
* the pump starts within the last 504 trading days ("recent" = last ~2 years),
* the peak is at least 10% (log) above trend,
* at least 10 days of data exist after the settle point.

Each candidate's window is a different length, so candidates are ranked by the
F-statistic of the episode model against a plain trend on the same window.

### 2. Signal score (0–100)

```
score = 100 · shape · sqrt(fit_gain · magnitude) · (1 if settle > start else 0.5)
  shape     = max(0, 1 − |r − 1| / 0.5)     how closely it settled on the trend
  fit_gain  = 1 − SSE_episode / SSE_trend   share of local off-trend variance the episode explains
  magnitude = min(1, h / 0.30)              pumps of 30%+ (log) above trend get full credit
```

### 3. Confidence: block-bootstrap null

Stock prices are close to random walks, and random walks constantly produce
bumps that look like pumps. For each stock, 200 synthetic paths are generated by
**stationary block bootstrap** of its own daily returns (mean block length 20
days). These paths keep the stock's drift, volatility, and short-range dependence,
but scramble any longer pattern. The full detector runs on every path.

* **`p_value`** = share of random paths that score at least as high as the real
  stock. **Confidence = 1 − p.**
* **Verdict:** `SUPPORTS` = `pump_revert` shape and p < α (default 0.10).
  `WEAK` = revert shape, but chance alone does that well.
  `PARTIAL` = `plateau_trend_catchup` or `pump_revert_below_start`.
  `CONTRADICTS` = some other shape.

### 4. Cross-sectional test

Per-stock p-values are noisy, so the report also asks whether the **group** of
stocks is more pump-and-revert than chance:

* the number of `pump_revert` shapes, compared with the number expected from each
  stock's null revert rate (simulated Poisson-binomial),
* the number of `SUPPORTS` verdicts, compared with Binomial(N, α),
* the median `r`.

### Other outputs per stock

`pump_pct`, `pump_excess_pct` (above trend), `peak_to_settle_pct` (the fall from
the fitted peak to the fitted settle level), `settle_vs_start_pct`,
`settle_vs_trend_pct`, `settle_vs_pretrend_pct` (an out-of-sample check: the trend
is fitted **only** on pre-pump data and extrapolated to the settle date),
`trend_cagr`, `start_date`/`peak_date`/`settle_date`, `pump_days`, `dump_days`.

## How reliable is it? (synthetic recovery test)

`python -m pump_dump.validate_synthetic` plants known shapes into random walks
(15%/yr drift; daily vol σ; pump of `h` over 50 days; settles over 100 days) and
counts how often the detector labels them correctly:

Measured with 30 trials per cell. A pump of `h` = 0.35 is about 42% above trend;
`h` = 0.60 is about 82%.

**Shape classified correctly**

| h | daily vol σ | revert | hold | crash | none* |
|---|---|---:|---:|---:|---:|
| 0.35 | 1.0% | 57% | 70% | 73% | 0% |
| 0.35 | 1.5% | 33% | 67% | 70% | 0% |
| 0.60 | 1.0% | 73% | 93% | 87% | 7% |
| 0.60 | 1.5% | 47% | 83% | 70% | 0% |

\* "none" = no planted pump. The detector almost always finds some ≥10% bump
in pure noise, which is why the bootstrap test is needed.

**Final verdict = SUPPORTS** (revert shape AND bootstrap p < 0.10, 100 nulls).
The `revert` column is the test's power. The other columns are false-positive rates.

| h | daily vol σ | revert | hold | crash | none |
|---|---|---:|---:|---:|---:|
| 0.35 | 1.0% | 47% | 23% | 7% | 3% |
| 0.35 | 1.5% | 13% | 10% | 3% | 10% |
| 0.60 | 1.0% | 60% | 7% | 0% | 3% |
| 0.60 | 1.5% | 33% | 13% | 3% | 7% |

On pure noise the SUPPORTS rate stays at or below α = 10%, so the test is
calibrated. The weak spots are low power on small pumps, and noisy pump-and-hold
paths that occasionally look like reverts.

**How to read this:**

* For mega-caps, idiosyncratic daily vol is about 1–2% (σ = 0.01–0.02). At that
  noise level, a 35% pump is hard to classify correctly. A 60%+ pump is classified
  reasonably well. The reason is that a random walk drifts about σ·√150 ≈ ±0.15
  log over a 150-day episode, which is a large fraction of `h`.
* On pure-noise paths (`none`), the detector almost always finds some ≥10%
  "pump", so the pump threshold alone cannot filter noise. The bootstrap p-value
  is what controls false positives (see the SUPPORTS-rate table).
* **Practical reading:** trust `SUPPORTS` verdicts on big pumps (`pump_excess_pct`
  ≥ ~50%). Treat the cross-sectional test as the main answer to "is this a pattern
  at all?"

## Caveats

* **Market-wide moves.** If the whole market pumped and dumped (for example a
  rally followed by a correction), many stocks will show the shape together. Run
  `--vs-market` to test the idiosyncratic version. Clustered `peak_date`s in the
  report are a hint that the move was market-wide.
* **"Linear" means constant growth rate.** The trend is a straight line in *log*
  price (constant % growth), which suits multi-year stock charts better than a
  straight line in dollars.
* **One episode per stock.** The detector reports only the most prominent recent
  episode.
* **Universe is a snapshot.** `universe.py` holds ~50 large S&P 500 names by
  market cap as of mid-2026. Pass `--tickers` or `--tickers-file` to refresh it.
